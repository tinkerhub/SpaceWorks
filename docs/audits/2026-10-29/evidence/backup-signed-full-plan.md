# Stage 1: usable, signed full deployment backup/restore

User scope: production-readiness audit and fixes. This plan fixes a confirmed unusable default backup/restore path; no production mutation, signing-key disclosure, new host topology, or weakened sovereign isolation is authorized.

## Confirmed current behavior

- archive_builder constructs CompoundCapture unconditionally for deployment. With zero sovereign slices the source verifier currently refuses because slice_entries and unsealed_slices are empty; even if admitted, outer-manifest contents omits keys/env.json and object bytes, so partial=False selects the legacy validator which refuses unlisted members.
- With sovereign slices the artifact format is intentionally B1, and restore.sh can only return/refuse compound-coordinator-ready. There is no shipped non-test run_compound_restore adapter/launcher.
- import-backup.sh validates static B1 format/signature, then installs continuity secrets and recreates app processes before the eventual unsupported-runtime refusal. Static artifact validity is not a claim of executable host readiness.

## Selected bounded correction

Add an explicit signed-full format `spaceworks-deployment-full-v1`, separate from unchanged B1 protocol v2. It is admissible only when the entire frozen retained makerspace population has superadmin access enabled and matching B1 activation state ON. Existing compound artifacts remain compound even when partial=False; never reinterpret them as legacy. Unsupported compound input is refused by the shipped import/restore request before mutations. Sovereign compound production/semantic verification stays implemented and must not leak rows; the report clearly identifies the absent production coordinator instead of claiming it is operational.

1. New full_capture.py and full_manifest.py (split validation/signing helpers as needed <=300 lines/file). Freeze population, access/activation, predecessor facts and capture id inside the SAME REPEATABLE READ exported snapshot used by pg_dump. Reuse existing snapshot payload assembly, object closure, quiescence, age encryption. Freeze and compare source database/server identity, exact dump hash, ownership digest. New format is signed with a separate length-framed Ed25519 domain over canonical manifest and exact complete content ledger (all dump, continuity-secret and object payload members; manifest itself excluded), existing configured host private/public key identity. Full manifest carries explicit full custody mode, no slices, all included IDs, empty excluded IDs, canonical platform recipient fingerprints, full storage/settings/build/PG facts required by existing restore. No private signing key or raw continuity-secret value is ever in manifest. Host configured BACKUP_ARCHIVE_VERIFY_PUBLIC_KEY is sole trust anchor; archive never supplies a trusted key.
2. Resolve full vs compound inside the exported snapshot, not by an earlier live query. _snapshot_payload accepts an explicitly owned capture policy so it can freeze once before capture and choose full only after full consent check. CompoundCapture stays unchanged for actual sovereign population. No automatic unsigned fallback. Source capture/promotion snapshot is immutable from the earlier freeze and cannot be fabricated from current live state or final manifest. Reject run-cohort drift or missing/divergent activation rows. Final publication locks and compares complete live cohort/access/activation against frozen facts; remote I/O occurs outside DB locks.
3. Keep current durable staging→stream-verify→conditional final→stream-verify→no-I/O promotion and reconciliation for the new format. Add strict explicit format dispatch to manifest verification and common component facts, not two weak parallel upload implementations. A signed-full envelope supplies the existing common identity/sets/component facts needed by artifact ledger and common promotion; source semantic digest clearly identifies this full format, never claims B1 partition/tenant closure proof. Use an independently frozen empty-slice closure digest only for the existing common success audit field; no invented source proof. Validate full format exact schema before common persistence/promotion. Existing B1 proof validator and its allowlist remain untouched. Failure and recipient-retention behavior stays current.
4. The signed-full complete ledger is validated against the decrypted tar and the extracted root: duplicate/unsafe/nonregular entries, missing/unlisted/tampered files, changed extracted manifest/keys refuse. Signature verification precedes environment/services/intent changes. Existing configured external source public key must match signer; cross-host operators must pin that key out of band on target before import (the archived keys/env.json remains limited to existing continuity-secret names and never replaces signing/verification trust).
5. Restore routing first dispatches explicit full format vs B1 vs old unsigned legacy. Signed full verifies signature+complete ledger+archive identity+build/OCI/PG/settings/storage compatibility before advancing any state; then executes existing supervised full in-place/disaster primitives. request_restore rejects known B1 inputs early with stable unsupported-host message (both full-looking and partial), leaving no restore row/audit/state mutation. Import preflight used by shipped script must reject B1 as unsupported before env write/restart; keep static B1 validator available for coordinator library tests through explicit parameter/call so artifact validity is not confused with host support. Unknown/new formats fail closed. Keep old legacy restore support for already available existing v1/v2/v3 unsigned archives; no new unsigned production.
6. Update source ownership/authority registry for any new paths and operator self-hosting/invariant notes. No API schema fields/routes needed if format is existing JSON field; regenerate only if actual response contract changes. Producer capability still verifies installed restore/import scripts, entrypoint, migrations and matching signing key before bytes. Extend marker/protocol claims explicitly for signed-full if required; don't call existing compound protocol range a new-format runtime attestation by implication.

## Tests, separate Stage 3

- Full capture uses exact exported snapshot and freezes all=true; zero tenant, one/multiple all=true, sovereign routes B1, missing/divergent activation, create/delete/change cohort during capture or remote upload rejects promotion; recipient switch and run cohort change refuse.
- Real age encryption + pg_dump/pg_restore roundtrip with objects/continuity keys, exact schema+rows checks against snapshot. No mocked dump presented as restore proof. Root controls DB runtime.
- Ed25519 wrong/unpinned signer, modified manifest/ledger, every payload class tampered, duplicate aliases, unsafe member/link, extra/missing file all refuse with no state/env/service effects.
- Same-host and cross-host preflight with externally pinned source verification key; archived self-key cannot authenticate. Signed full routes supervisor; B1 partial=False and partial=True refuse before any destructive work/config rewrite/restore intent. Old unsigned legacy still admissible only to legacy supported route.
- Durable upload failure/crash/reconcile/cleanup tests exercise exact shared protocol and final consent equality. False full schema field and signed but structurallyinvalid facts refuse.
- Host shell sequencing test asserts preflight refuses before `.env` install, service restart, registration and grants/restore effects. Integration test must not invoke real Docker/provider.
- Focused regression + full backup/migration run by root; no skip/xfail added as a substitute for results.

## Risks / limits

This fixes usable default all-platform-readable full deployment backup. It does not invent the missing sovereign coordinator launcher. That remains an explicit production limitation until separately implemented/verified. If review finds common durable B1 ledger cannot safely admit a distinct full format without schema/semantic abuse, require a revised plan instead of silently using ordinary non-durable upload or weakening signatures. No test or docs may call the overall backup subsystem production ready while that limitation remains.
