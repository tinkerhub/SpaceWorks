## Material limitations and exact integration blocker

The shipped `scripts/install-host-bundle.sh` fixed copy list does not install `scripts/restore-host.py` or refresh the host-side Python modules now required by the controller. That installer is outside this authorized source scope and was not edited. Therefore an ordinary existing-install update is **not a complete deployment of this change**: the new wrapper intentionally refuses missing or mismatched helper bytes before any operation. Parent must separately integrate packaging or install the complete matching guarded source set, with protected root-owned ancestry, together with its matching backend image. Do not advertise installed upgrade readiness until this is resolved and proven.

The existing producer capability still hashes the existing wrapper names. `restore.sh` now embeds exact SHA256 values for the transitive host controller/dependencies, verified with isolated stdlib Python before imports; `import-backup.sh` uses that same guarded entry. This binds delegated code through the existing capability mechanism without changing a frozen producer schema or source scanner. Any later host-code correction must deliberately regenerate the EXPECTED table and the new source freeze. Missing/tampered transitive code refuses. This does not replace signed image identity.

Supported source topology is a protected root-owned Linux checkout/install, local default Docker socket/context, the committed bundled family (none/build/tls/build-tls/saas/build-saas), unchanged Postgres16 service, image beat, exact shared application image with genuine repository digest, single redis://redis:6379/0 broker and one default queue. A build layer is usable only when its actual image has genuine matching RepoDigest facts. Cloud/external DB, external scheduler, custom commands/routes/brokers, inherited engine/project overrides, unknown writers, partial/compound B1, missing historical facts and incomplete recorded configuration refuse. Docker JSON/version behavior and root packaging still need real proof.

There is intentionally no automatic interrupted-destructive replay, old-env rollback, legacy journal replay for the new journal, failed-operation force-normal command, or bounded failed-restore unblocking receipt. Exact recorded OLD/NEW bytes/facts expose a torn configuration for review; an interrupted or unrecorded combination is never blessed or bypassed by refreshing wrapper records. A crash after terminal receipt but before marker replacement is also retained for manual completion, never SQL replay. Root resume accepts only a successfully quarantined operation with exact retained success phases and recovered-principal acknowledgement. An inability to stop/query Docker or SQL must be treated as unresolved writer exclusion, not proof of safety.

## Manual failure recovery and evidence retention

1. Keep ordinary writers stopped and retain the marker. A failed SQL command, a SQL exit0 rollback, an API acknowledgement or a successful grant command alone is not an unblock proof. If stop/query commands fail, independently establish actual process/session exclusion before any further maintenance; the marker does not stop already running writers.
2. Preserve the printed OPS/private/inplace-TOKEN directory, OPS/private/inplace-index-RESTORE_UUID.json, OPS/runs/RESTORE_UUID.jsonl, public sealed bundle/control/journal delegations and app work directory. Retain PRE_DB, target-before.json, environment-before.env, environment.old/new, configuration.json, resolved OLD/NEW and actual-container facts, input/operation/decision/marker records and every object rollback copy/version. Root-private material contains secrets: keep root ownership and mode0700 directories/0600 files; never chown it to app UID. App-readable sealed copies are separate, root-owned and non-writable.
3. Before root blocking, an explicit durable ABORT plus exact original NORMAL/identity/configuration proof is the only harmless release path. Failure alone does not rewind quiescence. Preserve evidence if the process ended before completing that path; do not invent a resume by deleting the work directory.
4. After blocking but before environment replacement, OLD files remain the reference. During environment replacement, compare every installed byte/hash to the privately recorded OLD or NEW bytes and each existing topology record; any other value is drift. A torn OLD/NEW pair remains blocked. Do not call setup/refresh merely to make the wrapper accept it, and do not bypass the wrapper to start application roles.
5. Once SQL began, retain the installed NEW or uncertain environment. Never automatically flip old keys while a partial source DB may be active. Recover only through a separately reviewed, operation-bound maintenance procedure under the same host lock: restore a complete known-coherent target SQL snapshot through the admitted bundled db transport, verify its original immutable row and grants through the fixed bootstrap, restore/verify every target object version/absence and ownership from independent evidence, and only then restore exact OLD env/topology bytes if recovering the old target. Root-private target identity is authoritative; source identity must never be adopted.
6. The new journal is not a signed old-target object snapshot or an automatic rollback receipt. Incomplete copy/upload outcomes and provider failures may require independent target object backups. Do not feed it to legacy reconcile-journal/rollback commands and assume equivalence. This source lane deliberately supplies no failed-restore marker-clear command; parent/operator must review a complete DB/object/key/identity verification and an explicit safe completion procedure before any unblock. When that proof is unavailable, retain the blocked gate and copies. Do not describe the operation as successfully rolled back.
