Behavior and reasons for the seams

- Queues.tsx uses a maker/session-keyed inner component and distinct modal-visit keys. The queue action scope additionally records modal kind and row ID. Same-row refetches retain draft/evidence state; closing/reopening and A→B→A create distinct owners. Capture-phase event fences cover unchanged modal controls synchronously.
- panels/useQueueActions.ts owns the existing queue modal state and complete assign→issue operation. It captures owner, origin maker/slug, row, paths and BOTH serialized bodies before the first TanStack mutation. It checks the original token inside each mutationFn and before stage two, UI success/error and cache publication. Its owner lock blocks same-tick duplicates and edits across the inter-stage gap. A ref retains known committed assignment for a current failed-issue retry; the row, evidence and scans are not replaced.
- QueuesInvalidation.ts recognizes assign-box container effects. An admitted assignment attempt also conservatively invalidates only the origin maker's containers/containers-all from finally, including ambiguous failure or stale-epoch decoding. Canonical staffRequest remains unchanged: no stale response body is inspected. An obsolete attempt never publishes assigned UI state, starts issue, or undoes server assignment. Known current success retains retry state; unknown commit cannot be represented as a known successful assignment.
- useHardwareQrVisit.ts reuses useAuthActionOwner for scope/epoch/mounted lifetime and records the original editable predicate for each scan. Separate camera-opening identity rejects retained native callbacks after close or replacement, including after later rerenders. Asset scans share a visit and remain concurrent; single-container/return scanners admit one callback per opening. This removes repeated scanner ownership mistakes from four hardware controls without introducing a new authentication layer.
- QueuesAssignIssueModal.tsx fences all assignment fields/scans and manual-entry handlers. Queue keys now own semantic reset, replacing the row-object effect that could wipe retry drafts. QueuesModalShared.tsx guards container loading, scan dispatch/result/error and manual/selection controls. QueueFormEditContext passes the parent's synchronous action fence into the existing return form's BoxCodeField without modifying that excluded modal source.
- DirectLoans.tsx captures borrower, items, QR payloads, container, evidence and remark before mutate; returns capture their path and serialized DTO including resolutions. Maker/session keys and issue/return visit keys prevent old callbacks entering a new form. Parent setters and nested controls synchronously reject pending or obsolete edits.
- useDirectLoanMutation.ts factors the duplicated direct issue/return command ownership and existing cache refresh rules into one domain hook. Both dispatch and completion require the original owner; stale callbacks do not refresh unrelated global caches or clear/toast newer forms. Current success preserves all prior loan/inventory/container/dashboard/accountability/fix-shelf invalidations.
- DirectLoanItems.tsx freezes item, quantity, removal, pasted QR and container paths while pending. Scan responses, error and finally paths require their originating form and camera visit. Container selection invalidates and closes an older camera; independent valid asset scans are retained.
- DirectLoanReturnModal.tsx guards native QR, evidence/notes and resolution setters, and uses a distinct return visit supplied by the parent. Same-loan refetch does not reset outcomes.
- DirectLoanBorrower.tsx captures the selected membership's waiver path/body and owner before mutate. Waiver pending/success/error are shown only for that subject. Borrower changes and nested walk-in callbacks check the handout lock and original borrower-choice visit.
- WalkInMemberForm.tsx serializes creation details before mutate and guards same-tick duplicate/edit routes. Successful creation refetches the originating roster before selection; the delayed selection still requires the original actor, form, borrower choice and handout intent. Committed creation is not cancelled/undone. Current creation/retry behavior remains available.
