## Confirmed findings

### U-F01 — per-room integration health never reaches the actual staff interface (P2)

`integrations/health.py::build_integration_health` included `chat_destinations`, but the original `admin_api/views_integration_health.py::IntegrationHealthSerializer` omitted it, so DRF dropped the subtree from GET responses. `frontend/src/features/staff/IntegrationHealthPanel.tsx` also declared/rendered only legacy email/Telegram/worker sections. Managers could receive an overall warning while being unable to see the Slack/Discord/Mattermost/Telegram room responsible. `tests/test_notification_destinations.py::test_health_reports_each_room_with_its_last_failure` inspected the builder directly and therefore missed both adapters.

Authorized corrective source: typed optional room/legacy serializers; safe bounded failure text rather than arbitrary historical provider text; module-aware actual staff rows in `IntegrationHealthDestinations.tsx`. Existing authorization, hidden/archived scope, legacy sender diagnostics and unknown-subsection resilience remain. Stage2 result/log: `/tmp/spaceworks-audit-utility-fixes-result.txt`, `.log`; Stage3 tests are written separately, execution is primary-owned.

### U-F02 — authoritative storage reconciliation omits issued PDFs and series images (P2)

Original `makerspaces/management/commands/recompute_storage.py::Command.handle` summed the other charged categories but omitted EventAttendanceCertificate. `_public_image_keys` included Event images but not EventSeries images. `events/services_certificates.py::_activate` charges immutable `size_bytes`; revocation deliberately retains issued bytes and charge. `events/services_series_images.py::update_image` also charges its image. Running reconciliation therefore overwrote usage with a smaller total, allowing effective managed storage-cap bypass and misreporting retained artifacts.

Authorized corrective source: add series keys to the existing shared set, deduplicating inherited occurrence references; sum immutable recorded sizes only for rendered ACTIVE or retained REVOKED certificates in the selected tenant. Pending/failed/rendering/never-issued revoked uploads are not charged. Preserve existing category accounting and storage-error refusal. Tests must cover exact per-tenant totals, repeated reconciliation, shared-key deduplication, revoked retention and image HEAD failure. Runtime remains pending.

### U-F03 — API-client usage drain has no recovery after detachment and can overwrite a competing drain (P2)

Original `apiclients/telemetry.py::flush_usage_observations` renamed a closed-minute hash to a fixed `:draining` key. A DB failure/process death after rename retained that key, but the next scan's `_parse_bucket` parsed the final token (`draining`) as a date and skipped it forever. A late writer recreating the original key plus a competing flusher could rename over the same drain destination. Authentication intentionally remains fail-safe; the consequence is lost/stale usage observations and incorrect operational liveness decisions.

Root confirmed and authorized the bounded fix: unique immutable `:draining:<uuid>` destination, recognize/retry both legacy and new drain shapes without renaming a detached bucket again, monotonic/idempotent DB updates, and delete only after successful persistence. Preserve two-day TTL and request-response isolation. Separate Stage2/3 artifacts: `/tmp/spaceworks-audit-telemetry-fix-result.txt`, `/tmp/spaceworks-audit-telemetry-tests-result.txt` and their logs. Existence of a result path is not a test-pass claim.

## Additional limitations kept explicit

- `seed_demo` is an operator-invoked development data writer with a documented default demo password and update-or-create resets. It refuses walk-in collisions, but it is not a production migration/repair command and should not be treated as one. The audit did not execute it or reset real inventory.
- `run_scheduled_tasks` deliberately claims cadence before executing a task, outside the row lock: at-most-once per cadence trades delayed retry for avoiding duplicate reminder sends. Failure isolation and `--due-only` behavior are source-documented and tested; this is not an exactly-once provider-delivery guarantee.
- The native-registration provisioning command has no dedicated command test located in this bounded search. Its source identity/idempotency and dry-run branch were read; related registration-auth tests do not substitute for executing that command.
- Readiness is a process/host/encryption readiness contract; integration health reports stored configuration/history/cache observations, not an active proof that SMTP/chat credentials work. Real provider and deployment probes remain unverified.
- Frontend route enumeration exposed `/admin/organizations` as an unsupported invitation destination: there is deliberately no organizations staff tab. Root corrected the existing handoff to the supported `/admin` entry and adjusted the component regression. Organization governance remains its separately scoped API/control-plane surface; this audit does not add a fabricated UI.
- The source pass does not remove the E-F06 tenant-purge durability or S-F02 atomic-publication release blockers. It also does not claim that every possible role×tenant×module×feature combination was exercised.
