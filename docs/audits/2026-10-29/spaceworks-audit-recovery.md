## Confirmed defects

### E-F01 — P2 dispatch outage leaves a quota-counted pending export

`backend/apps/data_export/views.py:65–68` commits `create_export_job`, then calls `.delay` without handling dispatch failure. `services.py:34–61` creates the PENDING row under the tenant quota lock. An unavailable broker therefore returns an uncaught 500 while the committed job occupies data-export quota until retention deletion. Unlike portable migration dispatch and backup dispatch, this path has no failed outcome.

Reproducer: replace `run_data_export_task.delay` with a broker `OperationalError`, submit an otherwise authorized REDACTED export; inspect response and persisted PENDING job. Minimal fix: typed 503, guarded terminal failure and failure audit; do not clobber a worker that already claimed/completed if dispatch acknowledgement is ambiguous. Missing regression: broker failure, no raw exception disclosure, no pending quota, late worker race.

### E-F02 — P2 a minted link outlives archive retention expiry

`backend/apps/data_export/services.py:224–238` consumption validates token lifetime but omits `job.expires_at`; issue-time checks alone are insufficient. A token minted one second before archive expiry can download for the remaining five-minute token lifetime if the periodic purge has not run. Backup token consumption already checks both deadlines.

Reproducer: available job expires at t+1; issue token; advance to t+2 (token remains live), consume token. Minimal fix: check archive expiry at consumption, clamp token expiry to archive expiry. Reject without consumption or downloaded audit. Missing regression: exact archive deadline boundary independent of token deadline.

### E-F03 — P2 hard worker failure leaves RUNNING forever

`services.py:111–137` claims only PENDING. `config/settings.py:530` configures late acknowledgement. A worker killed after claim loses its process; redelivery sees RUNNING and acknowledges a no-op. `deadline_at` is checked only inside the lost runner; no durable stale-export sweep existed. The UI and counted quota remain RUNNING for the seven-day retention period.

Reproducer: claim PENDING job; emulate process loss; run the task again before and after its deadline. Existing code never recovers it. Minimal fix: fenced expired RUNNING transition using stored deadline (started-at fallback), existing periodic task and redelivery recovery; preserve live workers; prevent late failure/finalization from overwriting recovered/available state. Missing regressions: live job exclusion, exact deadline, redelivery, stale worker and completion races, failure audit once.

### E-F04 — P2 archive-delete failure loses the durable retry locator

`backend/apps/data_export/tasks.py:15–34` deletes the row first. `signals.py:14–44` schedules byte deletion after commit; storage failure or a newly closed source gate only logs/skips after the row is gone. Bytes and charged usage survive without a durable retry row. `storage.delete_object` returns false on storage-client failures.

Reproducer: expired charged available job, storage delete returns false; invoke purge; row and locator disappear while bytes/accounting remain. Minimal periodic fix: successful byte deletion precedes row removal, preserve row/key/charge on failure, and prevent duplicate signal cleanup or storage credit; concurrent sweeps must be fenced. Direct deletes/cascades using only post-delete callbacks remain a separate durability concern unless covered by implementation. Missing regression: first failure retains state, next sweep deletes and frees once, overlapping sweep, frozen tenant, active worker never republishing deleted data.

### E-F05 — P1 backup reconciliation can tombstone its live producer

`backend/apps/backup/artifact_protocol.py` persists PENDING before publishing staging bytes. The producer holds `deployment_operation_lock` for its build/upload in `services_archives.run_archive`; `reconciliation.reconcile_artifact_uploads` ignores that lock. Its immediate PENDING scan sees neither staging nor final bytes during that valid interval, then `_tombstone` permanently fails the live artifact.

Reproducer: inside a mocked `upload_staging` before publishing bytes, invoke reconciliation; PENDING has no remote objects and is tombstoned. Existing `tests/backup/test_reconciliation_e5.py::test_pending_without_remote_bytes_is_failed_and_tombstoned` establishes the destructive branch; no producer/reconciler exclusion regression existed. Minimal fix: same nonblocking deployment-operation lock around the whole reconciliation including cleanup; skip when busy and retry on next scheduled run. Remote I/O stays outside database row locks. Also serializes concurrent reconcilers.
